## Goal

Performance stops being a one-off number: every recorded run appends a
ledger row, and CI fails a PR that regresses wall time or peak RSS beyond
tolerance on the standard workload.

## Verified Problem / Current Evidence

- `perf_250k.py` prints a number; nothing persists or compares it.
  Regressions are invisible until someone runs the bench manually.
- Field remediation verified 13.839 s / 478.5 MB — there is no guard
  keeping the next change from silently breaking the 15 s / 512 MB
  contract.

## Required Design / Decisions

1. `perf_250k.py --record` appends to `bench/LEDGER.jsonl`: one JSON row
   `{schema, git_sha, records, input_bytes, wall_s, peak_rss_mb, host_tag,
   py_version, os}` — dev artifact, never loaded at runtime. `host_tag`
   is a freeform local label (e.g. `i7-11800H-laptop`), no host fingerprint
   beyond it.
2. Ledger is committed history (small text file); rows are append-only —
   no rewrite, no dedup logic.
3. CI job `perf-gate` (new job in `ci.yml`, non-blocking-optional→
   required after calibration): runs `perf_250k.py` with tightened assert
   — fail if `wall_s > baseline * 1.25` or `rss_mb > 512`. Baseline read
   from the latest tagged ledger row for the same OS family; missing
   baseline → record-only, never fail.
4. Determinism note: the bench input is generated deterministically today;
   keep it so — wall/RSS vary, but input bytes must not.
5. `PERF_NOTES.md` gains a table of the last N recorded runs per host tag
   (generated by a small `scripts/bench_report.py` — optional, stdlib).

## Ordered Implementation Steps

1. `perf_250k.py`: `--record`, `--host-tag`, ledger writer (stdlib json;
   newline-append; fsync best-effort).
2. Seed ledger with the two known good runs (13.839 s/478.5 MB) as manual
   rows marked `source: field-remediation`.
3. CI job: run bench, append row to artifact (not commit — CI rows go to
   workflow artifacts; only maintainer-run `--record` commits).
4. Document in `RELEASING.md` perf-gate expectation + `PERF_NOTES.md`.
5. CHANGELOG Added (dev-facing).

## Required Tests / Validation Commands

```bash
uv run python bench/perf_250k.py --record --host-tag dev
python -c "import json; [json.loads(l) for l in open('bench/LEDGER.jsonl')]"
```

## Acceptance Criteria

- `--record` appends valid JSONL; malformed ledger never crashes the bench
  (reader skips bad lines).
- CI perf job runs on PRs, artifacts carry the row, and a deliberately
  slowed build fails the gate (proven once with a seeded sleep, reverted).

## Rollback / Stop Conditions

- Stop if CI runner variance makes the gate flaky (>2 false failures in a
  week) → relax tolerance or drop to advisory.

## Risks

- GitHub-hosted runner variance is real → tolerance 1.25× and OS-family
  baselines are the mitigation; do not tighten without data.

## Out of Scope

- Continuous benchmarking services (paid/third-party); per-commit bisect
  automation; perf dashboards.
