# SL206: Durable-prefix boundary violation

## Overview

`SL206` flags a Codex rollout file whose **durable record sequence does not
cover the envelope ordinals the resume path expects**. The Codex paginated
resume/fork machinery replays a contiguous durable prefix up to an
inherited-prefix ordinal; when the durable sequence stops short or has a
hole, the thread becomes unresumable while the file itself parses cleanly.

This is a Codex-rollout-scoped rule: the adapter normalizes per-record
durability into `extra_fields["codex"]` (`durable`, `ordinal`,
`envelope_type`, plus `item_type`, `has_encrypted_content`, and
`subagent_history_start_ordinal` where relevant), and the check runs only
when the detected format is `codex-rollout` — other adapters produce zero
findings and a coverage `adapter-not-applicable` skip.

Severity is `warning`; repairability is `manual` — the durable-prefix
contract is a vendor resume semantic. The engine never drops the
non-durable tail, reorders records, or synthesizes missing fields.

## Invariant

For a codex-rollout stream, the durable record sequence
(`session_meta`, `response_item`, `compacted` envelope families — the
records the rollout writer persists as thread history) must cover the
ordinal range the resume path replays:

- **`trailing-non-durable`**: the file declares an inherited-prefix
  ordinal (`subagent_history_start_ordinal` in `session_meta`) **past**
  the last durable ordinal — the resume path expects durable coverage
  through the claimed ordinal and finds a non-durable (or absent) record
  there instead. This is the openai/codex#40747 signature: `expected
  inherited prefix through ordinal 828, found final durable ordinal
  827`. One finding per file, anchored to the record holding the claimed
  ordinal (the claim itself sat on a non-durable `token_count` in
  #40747), else the file's tail record. A bare telemetry tail **without**
  the claim is normal rollout shape and stays silent.
- **`durable-gap`**: an ordinal strictly inside the durable range has **no
  record at all** — a dropped durable record holes the prefix. Ordinals
  held by non-durable records (`event_msg`, `turn_context`, `world_state`,
  telemetry) are legitimate interleave, never holes. One finding per
  file, at the first hole.
- **`missing-required-field`**: `reasoning` response items lacking
  `encrypted_content` while sibling reasoning items carry it — the
  resume projection may silently drop required reasoning state
  (openai/codex#19661). Uniform absence cannot prove the field is
  required and stays silent. One finding per file.

Evidence is structural only: `divergence`, ordinals, counts, and envelope
type names (schema vocabulary) — never payload content, never the
encrypted value.

## Cause

- A crash or interrupted flush leaving a trailing telemetry record
  (`event_msg`/`token_count`) as the highest-ordinal record — the
  #40747 failure: the child thread inherits a prefix claim through that
  tail ordinal but the parent's durable sequence ends earlier.
- A dropped durable record inside the stream (write loss, splice, or
  torn append) leaving an ordinal hole between durable records.
- A resume-projection bug writing `reasoning` items without
  `encrypted_content` into a stream whose other reasoning items carry
  it — mixed presence is the provable on-disk signature (#19661).

## False-Positive Notes

- **Version-dependence**: the durable-prefix contract is inferred from
  the vendor resume path's observed error semantics; pagination was
  reworked upstream (openai/codex#37577) and semantics may shift across
  CLI versions — severity stays `warning`, not `error`.
- `trailing-non-durable` fires only when the file itself declares
  `subagent_history_start_ordinal` beyond the durable prefix — the
  precondition is provable on disk. Rollouts routinely end with
  telemetry records (`token_usage_record`, `world_state`,
  `inter_agent_communication_metadata`) and no claim; those tails are
  healthy and silent. The declared claim still reports a structural
  precondition: severity stays `warning` because vendor semantics may
  shift across CLI versions.
- `durable-gap` requires the ordinal to be **absent entirely**; a
  non-durable record holding that ordinal is legitimate interleave and
  stays clean (healthy rollouts interleave `event_msg`/`turn_context`
  throughout).
- `missing-required-field` never claims the provider will reject the
  item — mixed presence is the only provable signal.

## Recipe or Manual Path

`SL206` has no automatic repair — dropping the tail or inventing fields
would edit evidence to match a contract the file never satisfied.

- `trailing-non-durable`: preserve the file as evidence; resume the
  thread by explicit id against the durable prefix (the vendor error
  names the durable boundary), or wait for the vendor fix. A
  drop-non-durable-tail copy-repair recipe may follow once the detector
  proves out — it is deliberately not automatic.
- `durable-gap`: the missing record is gone from this file; check sibling
  rollouts or the thread store for a copy before treating the session as
  recoverable.
- `missing-required-field`: treat affected reasoning items as opaque —
  their reasoning state is not reconstructible from this file.

## Example

`fixtures/adapters/codex/sl206_trailing_nondurable.jsonl` declares
`subagent_history_start_ordinal=5` in `session_meta` while the record at
ordinal 5 is a non-durable `event_msg`/`token_count` and the last
durable record is ordinal 4:

```text
sl206_trailing_nondurable.jsonl: WARNING SL206 — Non-durable tail record
past the durable prefix on line 6 for record <synthetic-id>
[divergence=trailing-non-durable, expected_durable_ordinal=5,
 last_durable_ordinal=4, inherited_prefix_ordinal=5, tail_ordinal=5,
 tail_envelope_family=event_msg]
```

The sibling `sl206_durable_gap.jsonl` (ordinal 2 absent entirely) and
`sl206_missing_field.jsonl` (one reasoning item with and one without
`encrypted_content`) each fire their own divergence; the conformance
`healthy.jsonl` — which interleaves `turn_context`/`event_msg` inside the
durable range — stays clean.
