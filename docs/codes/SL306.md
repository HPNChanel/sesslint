# SL306: Unknown non-linking metadata

## Overview

An existing Claude Code or Codex adapter encountered an unfamiliar metadata type
without known record-identity, linkage, replay-content or explicit critical
fields. This is an informational compatibility finding, aggregated by a bounded
type discriminator. It does not make the session invalid.

## Invariant

Unknown records with identity, parent, correlation, content, checkpoint or
explicit critical fields still produce SL302. Missing or invalid type markers
also remain critical. SL306 does not infer that an arbitrary future record is
safe to edit: it reports the narrower structural evidence available today.

## Cause

A vendor may add bookkeeping metadata independently of its replay record grammar.

## False-Positive Notes

An unfamiliar type may later acquire replay semantics that are not represented by
known field names. Review the vendor format before relying on a new shape. Known
fields are checked recursively; nested linkage is not treated as harmless.

## Recipe or Manual Path

There is no automatic recipe. Keep the original artifact and update the adapter
when its semantics are documented. Vendor write-back preserves these physical
lines verbatim. Canonical export remains a projection rather than a vendor copy.

## Evidence

The report contains only `count`, a bounded `type_value`, and `type_truncated`,
anchored at the first matching physical line. At most 32 distinct type groups
plus one overflow group are retained. Payload text is never included.

## Example

```text
INFO SL306 — Unknown non-linking metadata on line 3
count=2 type_value=future_status type_truncated=false
```
