# SL104: Multiple tool results

## Overview

- **Code**: `SL104`
- **Category**: `pairing`
- **Default Severity**: `error`
- **Default Repairability**: `manual`
- **Summary**: More than one result maps to one call.

## Invariant

A tool call must be answered by at most one tool result (unless provider-specific multi-part streaming is active).

## Cause

Duplicate delivery of webhook responses, worker retry yielding double results, or race conditions in event logger.

## False-Positive Notes

Duplicate results that are byte-identical may be safely collapsed.

## Recipe or Manual Path

If the duplicate tool results are byte-identical, `duplicate-projection-removal` collapses them safely. Conflicting results require manual review.

Policy: *May indicate duplicate responses or race conditions; manual review required.*
