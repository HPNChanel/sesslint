# SL205: Compaction coverage gap

## Overview

- **Code**: `SL205`
- **Category**: `checkpoint`
- **Default Severity**: `warning`
- **Default Repairability**: `manual`
- **Summary**: Boundary claims a covered span that is missing or
  non-contiguous.

## Invariant

A `compaction_boundary` carrying a coverage pointer asserts that prior
history up to a named leaf event was folded into the summary. For the
claim to hold:

- the referenced leaf must exist in the stream,
- it must strictly precede the boundary, and
- its ancestor chain must resolve — every parent link lands on an event
  that also precedes the boundary (the covered span is contiguous).

Adapters normalize vendor pointers into the adapter-neutral slot
`extra_fields["coverage"]["covered_through_id"]` — today only Claude
`summary` records (via `leafUuid` and bounded aliases) populate it.
Boundaries without a pointer are skipped silently: coverage is only
claimed where a pointer exists.

## Cause

Torn compaction projections that leave the ledger shorter than the
summary asserts, spliced histories where the leaf record was dropped but
the summary kept, merge tools that re-attach a boundary to the wrong
lineage, or hand-edited `leafUuid` values.

## False-Positive Notes

The check only fires on *definable* violations — a missing target or a
proven non-contiguous chain. Ambiguous leaf ids (duplicated, SL003
territory), absent pointers, and cycles in the ancestor chain (SL005
territory) never fire: coverage semantics there are unknowable and this
rule never guesses. Vendor compaction internals are opaque, so
"suspicious but structurally consistent" coverage stays silent by
design.

## Evidence

Structural facts only — never summary content:

- `boundary_id` / `record_id`: the compaction boundary record
- `covered_through_id`: the claimed leaf id
- `missing`: `true` when the leaf id does not exist in the stream
- `non_contiguous`: `true` when the leaf exists but fails the
  precedence/chain-contiguity check
- `boundary_index`: stream index of the boundary

## Recipe or Manual Path

No automated repair: which span a summary truly covers cannot be derived
mechanically — fabricating a pointer would invent lineage. Inspect the
boundary and its claimed leaf, verify the covered span by hand, and
re-attach or regenerate the summary.

Policy: *Coverage claims are verified, never guessed.*

## Example

```text
{"type":"summary", "leafUuid":"ghost-leaf", ...}
```

`ghost-leaf` appears nowhere in the stream — the summary asserts coverage
of events that do not exist. One `warning` naming the boundary record
with `missing: true`.
