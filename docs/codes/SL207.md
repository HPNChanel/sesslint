# SL207: Context-pressure projection

## Overview

SL207 warns when a codex-rollout session's last declared context
occupancy leaves less than 15% headroom under the declared model
window — the session is approaching the *context-deadlock* boundary:
too large to continue **and** too large to compact (the compaction
request itself must fit inside the window; contextspectre
`docs/deadlock.md`).

Codex-rollout `event_msg/token_count` records carry both halves of the
comparison on disk:

- `info.last_token_usage.input_tokens` — the vendor's own per-request
  context footprint (the input side is what occupies the window;
  `cached_input_tokens` is a subset of it, not an addition).
- `info.model_context_window` — the model's declared window limit,
  recorded per event. Because the window is *declared in the file*, no
  profile constant or version lookup is needed and the value follows
  whatever model/plan the session actually ran under.

Two counters are deliberately **not** used: `info.total_token_usage`
and `token_usage_record.thread_token_usage` are cumulative lifetime
billing totals — on real corpora they routinely exceed the window by
orders of magnitude. Mapping them to window occupancy would be the
wrong counter and produce false confidence.

The check is adapter-scoped (`codex-rollout` only — other formats do
not declare a window on disk) and absence-tolerant: files without
`token_count` markers, or markers lacking a declared window, stay
silent with no coverage noise.

## Invariant

For the last `context_pressure` marker in the stream:

```
headroom = window_limit - context_tokens
fires    ⇔  headroom × 20 < window_limit × 3      (headroom < 15%)
```

Integer arithmetic only — deterministic on every platform. The last
marker wins: pressure is a point-in-time signal, and a later marker at
lower occupancy (post-compaction) correctly reports the current state.

## Cause

Normal session growth. The finding fires when the session's context
footprint approaches the model window — the risk window where
auto-compaction can fire late and lose intent (claude-code#18720,
#29890, #75759) or fail outright because the compaction request no
longer fits.

## False-Positive Notes

- **Metered under-reporting**: the metered footprint may exclude
  system-prompt/tool/framework overhead (the deadlock reference
  estimates 40–60K tokens beyond conversation). The 15% margin is a
  floor, not a guarantee — true headroom may already be smaller. The
  detector errs on the side of the declared numbers.
- **Window re-declaration**: if the declared window changes mid-file
  (model/plan switch), only the last declaration applies.
- **Occupancy ≠ billing**: `context_tokens` is the last request's input
  footprint, not lifetime usage — a low-pressure session can still have
  enormous cumulative billing counters without triggering SL207.

## Recipe or Manual Path

Manual (`manual`): compact or checkpoint now — continued growth risks
an un-compactable deadlock. SessLint never edits usage markers, window
declarations, or session content to buy headroom.

## Example

```json
{
  "code": "SL207",
  "severity": "warning",
  "source": {"path": "rollout-example.jsonl", "line": 4},
  "evidence": {
    "context_tokens": 243127,
    "window_limit": 258400,
    "headroom": 15273,
    "threshold_source": "declared-window:15pct-headroom",
    "last_marker_line": 4
  }
}
```

## Tested Fixture

- Path: `fixtures/adapters/codex/sl207_near_limit.jsonl` — last marker
  at ~94% occupancy → fires once, anchored at that marker's line.

Companion fixtures in the same directory: `sl207_healthy.jsonl` (~58%
occupancy → silent), `sl207_no_window.jsonl` (`token_count` without
`model_context_window` → silent), `sl207_no_marker.jsonl` (no
`token_count` records → silent).
