# SL002: Torn terminal record

## Overview

- **Code**: `SL002`
- **Category**: `syntax`
- **Default Severity**: `error`
- **Default Repairability**: `deterministic`
- **Summary**: Distinguish an incomplete final append from malformed data followed by later records.

## Invariant

A session stream must terminate cleanly after a complete record. Any final non-empty line must be fully formed or flagged as an incomplete terminal append.

## Cause

The writing process was killed mid-write (SIGKILL, power cutoff, or disk exhaustion) before the trailing record could be completed and flushed with a newline. A final line whose only defect is a lone surrogate (for example `\ud800`) is the same terminal failure: one SL002 finding, and the check does not abort. Its Why line names the code point (`Line N contains a lone UTF-16 surrogate (\ud800) and cannot be decoded as a session record`). An ordinary torn append still says `Torn terminal record on line N for record …`.

## False-Positive Notes

Active live streams being tailed or read concurrently may temporarily exhibit torn terminal records if read mid-flush.

## Recipe or Manual Path

Deterministic automated repair via the `torn-terminal-record-discard` recipe, provided no irreversible side-effecting action occurred after the cut point.

Policy: *Only terminal incomplete records qualify; repairable by conservative suffix drop.*
