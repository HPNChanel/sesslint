# SL402: Session-index divergence

## Overview

`SL402` flags disagreement **between a vendor session index and the on-disk
session set** — the scan-level complement to SL401. Where SL401 resolves
links *between files*, SL402 diffs the *set against its index*.

Agents like Claude Code keep a `sessions-index.json` beside session ledgers
so the picker can list sessions without parsing every file. When the index
and the files drift apart — a ledger written but never indexed, an index
entry pointing at a deleted file, or a truncated index left by a crash —
resume/discovery silently degrades: sessions exist but are invisible to the
picker, or the picker offers sessions that no longer exist.

This is a scan-layer detector: it runs during `sesslint scan` directory
walks and `--agent` root scans, after all per-file results are collected.
Single-file `sesslint check` never emits `SL402` — one file cannot prove
index absence or membership.

## Invariant

For every in-scope `sessions-index.json` beside scanned session files:

- If the index parses completely, every indexable sibling ledger must appear
  in it, and every index entry must resolve to a file.
- If the index is malformed or truncated, the index itself is the finding —
  no membership claims are derived from an unproven index.
- A missing index is **not** a finding: fresh installs and directories that
  simply contain exports have no index to disagree with.

Divergence kinds (`evidence.divergence`):

- `file-not-in-index` — an indexable session file (a ledger the adapter
  identified as the vendor's primary session format) is absent from a
  cleanly parsed index. Emitted on the file's `FileResult` with
  `resolution: "missing"`, `session_id_hash8`, `index_entry_count`. Warning.
- `index-entry-no-file` — an index entry claims a session (via `sessionId`
  and/or `fullPath`) that resolves to nothing: no scanned sibling, no
  member session id, no file on disk. Emitted once per entry on the index's
  `FileResult` with `resolution: "dangling"`, `entry_id_hash8`. Warning.
- `index-malformed` — the index cannot be parsed at all. One finding on the
  index's `FileResult` with `resolution: "unparseable"`, `error_kind`.
  Membership is never inferred from an unparseable index.
- `index-truncated` — the index is JSON-shaped but cut mid-structure (the
  picker-crash signature). One finding with `resolution: "truncated"`,
  `parsed_entry_count`. Salvaged partial entries support no claims.

Only files the adapter layer identifies as the index's vendor format count
as membership candidates. Sidecars, sub-agent logs, `file-history`
snapshots, and undetected `.jsonl` siblings can exist without index
membership — they are never flagged (though their presence on disk still
satisfies dangling checks, since an index entry is only dangling when the
file provably does not exist).

## Cause

- A session file was written or copied in while the agent was not running,
  so the index was never updated — the picker cannot see it.
- A ledger was deleted outside the agent, leaving a dangling index entry —
  the picker offers a resume target that fails.
- The agent crashed or was killed mid-write, leaving a truncated index
  (upstream: picker crashes on truncated `sessions-index.json`).
- Hand-editing or third-party tools rewrote one side but not the other.

## False-Positive Notes

- **Scope-filtered files are not dangling entries**: if `--exclude`/`--ext`
  filters a ledger out of the scan, the on-disk existence check still
  satisfies its index entry. Divergence is about existence, not scan scope.
- **Renamed files are members by identity**: a file whose `sessionId`
  matches an index entry counts as indexed even under a different filename.
- **Incomplete indexes cannot prove absence**: entries lacking `sessionId`,
  unrecognized index shapes, and truncated indexes suppress
  `file-not-in-index` — the detector fails closed rather than guess.
- **Non-Claude indexes**: currently only `sessions-index.json` (Claude
  layout) is reconciled. Other vendor index stores are discovered as a
  limitation, not flagged.

## Recipe or Manual Path

`SL402` is **manual** repairability: SessLint never deletes or rebuilds
vendor state.

- `file-not-in-index`: the session file is intact — explicit-id resume may
  still work even though the picker hides it. Restarting the agent or
  removing the stale index typically forces the vendor to rebuild it.
- `index-entry-no-file`: the index entry is stale metadata. Deleting or
  regenerating the index clears it; the missing session cannot be
  recovered from the index alone.
- `index-malformed`/`index-truncated`: back up the file if it matters, then
  let the vendor regenerate it — the corrupted index is the problem, not
  the sessions.

## Example

`fixtures/scan/index_divergence/missing_member/` holds three session files
with an index listing two; `dangling/` adds an index entry with no file.

```text
sess-c.jsonl: WARNING SL402 - Session file is not listed in the vendor
session index [divergence=file-not-in-index, resolution=missing]

sessions-index.json: WARNING SL402 - Vendor session index entry has no
matching session file [divergence=index-entry-no-file, resolution=dangling]
```

The `absent/` sibling tree (sessions, no index) produces zero `SL402`
findings — absence of an index is normal, not divergence.
